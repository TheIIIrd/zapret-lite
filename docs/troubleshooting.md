# Когда не работает

Начинайте отсюда:

```sh
zapret-lite doctor
```

Он проверяет окружение, целостность установки, конфигурацию, списки и
службу — и говорит, что именно сломано. Дальше по симптомам.

## Служба не запускается

```sh
journalctl -u zapret -n 50
```

Частые причины:

**Не загружен `nfnetlink_queue`.** Без него nfqws не получит ни одного
пакета.

```sh
sudo modprobe nfnetlink_queue
echo nfnetlink_queue | sudo tee /etc/modules-load.d/zapret.conf
```

**Нет nftables или iptables.** Установите один из них пакетным
менеджером своего дистрибутива.

**Порт очереди занят другим процессом.** Проверьте, не запущен ли второй
экземпляр zapret: `ss -tulpn | grep nfqws` и `systemctl status zapret`.

## Обход перестал работать сам по себе

Если nfqws упал, служба **не считается упавшей**: у неё `Type=forking`
без главного PID, systemd следит за cgroup, и опустевшая cgroup для
него — штатное завершение. Поэтому drop-in задаёт `Restart=always`, а
не `on-failure`: последний на успешное завершение не реагирует.

Проверить, что перезапуск работает:

```sh
sudo pkill -x nfqws
sleep 8
systemctl status zapret     # должна быть active (running)
```

## Служба работает, но обхода нет

**Сначала проверьте, не виртуальная ли машина.** VMware и VirtualBox с
внутренним NAT ломают большинство техник обхода: DPI видит не то, что
отправил nfqws. Можно перебрать все двадцать стратегий и не получить
результата, причём ни одна из них не виновата.

```sh
systemd-detect-virt --vm
```

Если `vmware` или `oracle` — переключите сеть машины с NAT на мост
(bridged). `zapret-lite doctor` предупреждает об этом сам.



На физической машине это почти всегда дело в стратегии: провайдеры
блокируют по-разному, и подходящую приходится подбирать.

```sh
zapret-lite list
sudo zapret-lite use general-alt2
```

Перебирайте по одной, проверяя после каждой. Начните с `general`, потом
`general-alt`, `general-alt2` и дальше. Вариантов больше двадцати —
какой-то подойдёт.

Если раньше работало, а теперь нет, и вы недавно обновлялись:

```sh
zapret-lite rollback
```

## Discord работает, голос — нет

Голосовой трафик Discord идёт по UDP на портах, которые по умолчанию не
обрабатываются. Включите игровой фильтр:

```sh
sudo zapret-lite game-filter all
```

Учтите, что фильтр захватывает диапазон 1024-65535 по TCP и UDP, то есть
заметно больше трафика; это нагрузка на CPU.

## Часть сайтов не открывается, а `doctor` говорит про IPv6

Если у вас двустековое подключение, а `DISABLE_IPV6=1`, обход к IPv6
просто не применяется - хотя стратегия может быть верной:

```sh
sudo zapret-lite ipv6 on
```

Проверить, есть ли глобальный IPv6: `ip -6 addr show scope global`.

Выбор сохраняется и переживает обновление. При установке то же самое
задаётся флагом `--ipv6`.

## Работает, но всё тормозит

Уменьшите область обработки:

```sh
sudo zapret-lite game-filter disabled
sudo zapret-lite ipset none
```

`ipset none` отключает проверку по списку из 32 тысяч подсетей, которая
выполняется в userspace. Если после этого нужные сайты перестали
открываться, верните `loaded`.

## Часть сайтов открывается, часть нет

Добавьте домены в свой список:

```sh
echo 'example.com' | sudo tee -a /etc/zapret-lite/lists/list-general-user.txt
```

Перезапуск не нужен: nfqws перечитает файл сам.

Обратная ситуация — сайт сломался из-за обхода — решается исключением:

```sh
echo 'example.com' | sudo tee -a /etc/zapret-lite/lists/list-exclude-user.txt
```

**Не оставляйте эти файлы пустыми.** Пустой список означает не «ничего»,
а «без ограничений»: nfqws может снять фильтрацию целиком и начать
обрабатывать все домены подряд. Оставьте хотя бы строку-заглушку.

## Установщик отказывается работать

**«config изменён вручную»** — вы правили `/opt/zapret/config`, а он
генерируется. Перенесите правки в `/etc/zapret-lite/local.conf` и
повторите. Если правки не нужны, `--force` сделает копию и перезапишет.

**«манифест не сходится»** — архив повреждён или изменён. Скачайте
заново и сверьте контрольную сумму из релиза.

**«в комплекте нет бинарников zapret»** — вы ставите из дерева
репозитория. Бинарники в git не хранятся, они добавляются при сборке
релиза. Возьмите комплект со страницы Releases или соберите zapret сами
(см. ниже).

## «install_bin.sh не нашёл бинарник»

В комплекте нет сборки под вашу архитектуру, либо она не запускается на
этой системе (`install_bin.sh` это проверяет, а не только смотрит на имя
каталога).

Соберите из исходников:

```sh
sudo apt-get install make gcc zlib1g-dev libcap-dev \
                     libnetfilter-queue-dev libmnl-dev libsystemd-dev
git clone https://github.com/bol-van/zapret /tmp/zapret
cd /tmp/zapret && git checkout 87e058624c72863db53bdaf7fb6f16576dddb6ab
make systemd
cp -r binaries/my <каталог-комплекта>/zapret/binaries/
```

Затем повторите установку. Список пакетов взят из инструкции апстрима;
на не-Debian дистрибутивах найдите аналоги dev-пакетов.

## Сосуществование с другими правилами firewall

zapret-lite не навязывает тип firewall: работает автоопределение
апстрима. Если у вас уже есть правила iptables — например, рядом с
WireGuard, — зафиксируйте выбор явно:

```sh
sudo zapret-lite fwtype iptables
```

Или сразу при установке: `sudo ./install.sh --fwtype iptables`.
Посмотреть текущее состояние — `zapret-lite fwtype` без аргументов.

### Когда проверка срабатывает

Установщик проверяет зависимости **до единого изменения в системе** —
до остановки службы и копирования файлов. Если чего-то не хватает, он
отказывается сразу и ничего не трогает: работающая установка остаётся
работать.

Проверяется тот тип, который будет использован фактически: заданный
флагом, сохранённый с прошлого раза или выбранный автоопределением.

`zapret-lite fwtype` отказывается переключаться по той же причине и не
меняет сохранённое значение при неудаче.

**Режиму iptables нужен пакет `ipset`.** Апстрим перечисляет их вместе
(`common/installer.sh:633`), а скрипт создания списков вызывает
`ipset -! restore`. В Debian, Ubuntu и Mint `ipset` по умолчанию не
установлен, и без него служба стартует, а правила не применяются —
выглядит это как «переключил, но ничего не изменилось».

```sh
sudo apt install iptables ipset        # Debian, Ubuntu, Mint
sudo pacman -S iptables ipset          # Arch
sudo dnf install iptables ipset        # Fedora, RHEL
```

`zapret-lite fwtype` подскажет команду для вашего дистрибутива сам.

`zapret-lite fwtype` откажется переключаться, если чего-то не хватает,
и назовёт недостающие команды. `zapret-lite doctor` отдельно проверяет,
что правила действительно есть в выбранной подсистеме.

## «Start request repeated too quickly»

Служба отказывается стартовать после нескольких переключений подряд.
Это ограничитель systemd: он защищает от аварийного цикла
перезапусков, но не отличает его от намеренных действий.

Каждое переключение стратегии, типа firewall, IPv6, игрового фильтра
или интерфейса останавливает и запускает службу. Ограничитель настроен
близко к штатному для systemd, а намеренные операции дополнительно
сбрасывают счётчик, так что упереться в него трудно. Если всё же
уперлись:

```sh
sudo systemctl reset-failed zapret
sudo zapret-lite restart
```

## Слишком много сетевых интерфейсов

По умолчанию zapret обрабатывает трафик на всех интерфейсах. На машине
с docker, WireGuard и мостами это лишняя работа, а иногда и вред:
правила цепляют трафик, которому обход не нужен.

```sh
sudo zapret-lite wan-iface eth0
```

Имя стоит проверить: `ip -o link show`.

Опечатка коварна: в режиме nftables служба стартует **нормально** — имя
просто кладётся в набор, — но правила не совпадают ни с чем, и выглядит
это как неработающая стратегия. `zapret-lite doctor` проверяет, что
указанный интерфейс существует. Если служба всё же не поднимется,
значение вернётся к прежнему автоматически.

Несколько интерфейсов — через пробел в кавычках: `"eth0 wlan0"`.
Вернуть обработку всех — `any`. При установке: `--wan-iface eth0`.

Посмотреть список интерфейсов и текущий выбор: `zapret-lite wan-iface`
без аргументов.

Под капотом это `IFACE_WAN` апстрима: правила nfqws получают привязку
`oifname @wanif` (`common/nft.sh`, `_nft_fw_nfqws_post4`).

Перед первой установкой стоит снять снимок и сверить его после удаления:

```sh
sudo iptables-save > /tmp/before          # до установки
# ... установка, работа, удаление ...
sudo iptables-save > /tmp/after
diff /tmp/before /tmp/after                # должно быть пусто
```

Если после удаления остаются правила zapret, значит служба была
остановлена не через `uninstall.sh`, а файлы уже снесены. Восстановить
можно так: поставить заново, остановить службу штатно, потом удалять.

Отдельно про nftables: сам zapret снимает только цепочки, а пустую
`table inet zapret` с сетами оставляет — функция `nft_del_table()` в его
`common/nft.sh` определена, но не вызывается. `uninstall.sh` убирает её
сам, но только если цепочек в ней уже нет. Вручную:

```sh
sudo nft delete table inet zapret
```

## Ничего не помогло

Соберите информацию перед тем, как спрашивать:

```sh
zapret-lite status
zapret-lite doctor
journalctl -u zapret -n 100 --no-pager
nft list ruleset 2>/dev/null | head -50
```

Полезно также приложить название провайдера и что именно не работает —
подбор стратегии сильно зависит от того, как блокирует конкретный
оператор.
