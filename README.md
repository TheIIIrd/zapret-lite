# zapret-lite

Установка [zapret](https://github.com/bol-van/zapret) на systemd-дистрибутивы
GNU/Linux и запуск одной из готовых стратегий
[flowseal](https://github.com/Flowseal/zapret-discord-youtube).

Только базовый функционал: поставить, выбрать стратегию, откатиться, если
стало хуже.

## Что это и чем отличается

Это **обвязка, а не форк**. Апстримный zapret ставится как есть, со своими
правилами firewall и init-скриптом. Мы добавляем сверху то, чего в нём нет:
каталог готовых стратегий, установщик, менеджер и механизм отката.

Стратегии flowseal рассчитаны на Windows и на Linux напрямую не работают.
Конвертер переводит их автоматически — по формальным правилам, с проверками
на каждом шаге. Ручной перенос ошибается: в форке, откуда я начинал, в 19
конфигах из 20 подставлен не тот фейковый пейлоад, в одном опечатка в имени
файла, в одном ссылка на файл, удалённый из апстрима полгода назад, и порты
firewall не совпадают со стратегиями, из-за чего часть профилей мертва.

Поддерживаются Debian, Ubuntu, Mint, Fedora, RHEL, openSUSE, Arch и
производные — всё, где есть systemd и nftables либо iptables.

## Установка

Готовый комплект берётся со страницы
[Releases](../../releases/latest) — там архив и файл с контрольной
суммой. Одной командой:

```sh
REPO=<владелец>/zapret-lite
URL=$(curl -fsSL "https://api.github.com/repos/$REPO/releases/latest" \
      | grep -oE '"browser_download_url":[[:space:]]*"[^"]*\.tar\.gz"' \
      | cut -d'"' -f4)
curl -fLO "$URL" && curl -fLO "$URL.sha256"
sha256sum -c "$(basename "$URL").sha256"
tar -xzf "$(basename "$URL")"
cd "$(basename "$URL" .tar.gz)"
sudo ./install.sh
```

Имя архива содержит версию, поэтому постоянной ссылки на «самый свежий»
нет — её приходится узнавать у API. С установленным `gh` проще:

```sh
gh release download --repo <владелец>/zapret-lite --pattern '*.tar.gz*'
```

Если архив уже скачан вручную:

```sh
sha256sum -c zapret-lite-<версия>.tar.gz.sha256
tar -xzf zapret-lite-<версия>.tar.gz
cd zapret-lite-<версия>
sudo ./install.sh
```

Контрольная сумма подтверждает, что архив скачался целиком. Подлинность
она не доказывает: криптографической подписи у проекта пока нет
(см. [docs/security.md](docs/security.md)).

Архив самодостаточный: бинарники zapret внутри, сеть при установке
не нужна. Это намеренно — github.com может оказаться заблокирован ровно
у того, кому нужен обход.

Выбрать стратегию сразу: `sudo ./install.sh --strategy general-alt11`.
Посмотреть, что будет сделано, ничего не меняя: `--dry-run`.

Если у машины есть глобальный IPv6, добавьте `--ipv6`. По умолчанию
обрабатывается только IPv4 — так же, как в апстримном zapret, который
задаёт этот вопрос при установке. Без этого часть трафика к
заблокированным ресурсам пойдёт мимо обхода, и выглядеть это будет как
неподходящая стратегия. Проверить: `ip -6 addr show scope global`.

## Использование

```
zapret-lite status              что сейчас происходит
zapret-lite list                доступные стратегии
zapret-lite use <имя>           переключить стратегию
zapret-lite doctor              диагностика
zapret-lite generations         установленные поколения
zapret-lite rollback            вернуться к предыдущему
zapret-lite ipset <режим>       loaded | none | any
zapret-lite game-filter <режим> disabled | all
zapret-lite ipv6 <режим>        on | off
zapret-lite fwtype <тип>        auto | iptables | nftables
zapret-lite wan-iface <имя>     только этот интерфейс, any — все
zapret-lite check-update        есть ли новые стратегии
```

Если что-то не работает, начинайте с `zapret-lite doctor`. Он проверяет
окружение, целостность установки, конфигурацию, списки, права и службу —
включая разбор опций самим движком через `nfqws --dry-run` — и говорит,
что именно сломано.

## Обновление и откат

Обновление — это запуск `install.sh` из нового архива. Стратегия, списки
и настройки сохраняются.

Каждая установка создаёт **поколение** — неизменяемый снимок стратегий,
списков и фейковых пейлоадов. Переключение между ними атомарно и не
требует сети:

```sh
zapret-lite rollback            # к предыдущему
zapret-lite generations         # посмотреть все
zapret-lite rollback <имя>      # к конкретному
```

Откат работает и через минуту после обновления, и через месяц. Это важнее
любого автоотката: обход обычно ломается не сразу, а через час-другой,
когда окно автоматической проверки давно закрылось.

Хранится три поколения. Ваши файлы в `/etc/zapret-lite` поколениями не
управляются и при откате не трогаются.

Проверка обновлений включена и **только уведомляет** — раз в сутки пишет
в журнал, если у flowseal появились новые стратегии. Ничего не скачивается
и не применяется: обновляться имеет смысл тогда, когда что-то перестало
работать, а не по расписанию.

## Настройка

| Файл | Назначение |
|---|---|
| `/etc/zapret-lite/local.conf` | ваши правки, перекрывают всё остальное |
| `/etc/zapret-lite/lists/*-user.txt` | ваши домены и исключения |
| `/etc/zapret-lite/strategy` | выбранная стратегия |
| `/etc/zapret-lite/update.url` | свой источник проверки обновлений |

Конфигурация складывается из трёх слоёв: умолчания → стратегия →
`local.conf`. Например, чтобы принудительно использовать iptables:

```sh
echo 'FWTYPE=iptables' | sudo tee -a /etc/zapret-lite/local.conf
sudo zapret-lite restart
```

`FWTYPE` по умолчанию не задан — работает автоопределение апстрима. Если
у вас уже есть правила iptables (скажем, рядом с WireGuard), навязывать
nftables мы не будем.

Ограничить обработку одним интерфейсом (полезно там, где много лишних —
docker, мосты, VPN):

```sh
sudo zapret-lite wan-iface eth0
```

**Не редактируйте `/opt/zapret/config`.** Он генерируется, и установщик
откажется работать, заметив ручные правки. Всё, что вы хотите изменить,
пишется в `local.conf`.

## Удаление

```sh
sudo ./uninstall.sh             # сохранит /etc/zapret-lite
sudo ./uninstall.sh --purge     # удалит всё
```

Служба останавливается до удаления файлов — иначе правила firewall
останутся в системе, и снять их будет уже нечем. После удаления стоит
убедиться:

```sh
nft list ruleset | grep -i zapret
iptables-save | grep -i zapret
```

Оба вывода должны быть пустыми.

## Чего здесь нет

- Не Windows: для неё есть [flowseal](https://github.com/Flowseal/zapret-discord-youtube).
- Не для роутеров и не для OpenWrt: только systemd-дистрибутивы.
- Нет tpws, автообновления списков из реестра, blockcheck в меню.
- Нет автоотката: сигнал «работает или нет» слишком шумный, чтобы
  доверять ему решение. Откат остаётся вашим, зато всегда доступен.

## Безопасность

- Апстримный zapret запинен по хешу коммита, не по тегу.
- Всё содержимое комплекта проверяется по `MANIFEST.sha256` перед
  установкой; несовпадение прерывает её.
- Стратегии не берутся из чужих форков: они генерируются из релиза
  flowseal формальным конвертером, и любая непонятная конструкция валит
  сборку, а не проходит молча.
- Синхронизация с flowseal автоматическая, но **мерж — ручной**. Между
  чужим репозиторием и файлом, который читается с правами root, всегда
  стоит человек.
- Установщик не угадывает способ повышения прав, не трогает `sysctl`,
  SELinux, `/etc/hosts` и `~/.bashrc`, не скачивает ничего из сети.
- Юнит проверки обновлений работает под `DynamicUser` с пустым
  `CapabilityBoundingSet` и `ProtectSystem=strict`. Службе zapret такой
  sandbox не подходит — ей нужен root для правил firewall, — и в drop-in
  объяснено, почему его там намеренно нет.

Подробнее: [docs/security.md](docs/security.md).
